# Putting the VGR Brand Search Interest on your VGR "Intelligence" page (auto-publishing)

Same mechanism as **VGR 40** — two things live in the cloud so your PC never has
to be on for the page to stay up:

1. **A data feed** — `brand_index_data.json` (the index method + all 500 brands
   with VGR interest, % vs last month, and the per-source google-search /
   google-news / wikipedia levels). Regenerated by `python dashboard.py`.
2. **A publisher** — a free **GitHub Action**
   (`.github/workflows/refresh-index.yml`) rebuilds the dashboard + JSON from the
   committed data and publishes them to **GitHub Pages** on every push (and a
   weekly safety re-publish). No computer of yours needs to be on.

```
https://<user>.github.io/<repo>/                       <- the ready-made dashboard
https://<user>.github.io/<repo>/brand_index_data.json  <- the data feed (CORS-open)
```

> **One difference from VGR 40.** VGR 40 re-pulls live market data (Yahoo) in the
> cloud each day, so its Action fully rebuilds the index unattended. The Brand
> Index's inputs (Google Trends / News via pytrends, Wikipedia pageviews) are
> rate-limited and collected **locally**. So the cloud Action does **not**
> re-collect — it deterministically re-renders the site from the CSVs you commit.
> **To refresh the numbers:** run the collection locally, commit the new
> `refresh_500/*.csv`, and push — the Action republishes automatically.

## Step 1 — put the project on GitHub (one time)

Create an **empty** repo named `vgr-brand-search-interest` on github.com/almarpause, then:

```bash
cd C:\Users\aresi\Claude\code\brand-index
git add .
git commit -m "VGR Brand Search Interest — website payload + publisher"
git remote add origin https://github.com/almarpause/vgr-brand-search-interest.git
git push -u origin master
```

Or just double-click **`push.bat`** (it wires the remote and pushes `master`).

## Step 2 — turn on Pages + let the Action run

- On GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
- **Actions** tab → run **"Refresh VGR Brand Search Interest"** once (`Run workflow`) to
  publish immediately; after that it re-publishes on every push and weekly.
- Your dashboard is now live at `https://<user>.github.io/<repo>/`.

## Step 3 — show it in the VGR Intelligence section

### Option A — fastest: embed the ready-made dashboard (iframe)
Drop this into your Intelligence page in Lovable. It always shows the latest
published version; nothing else to maintain:

### Option B — native VGR styling: read the JSON and render it yourself
Paste this component into your Lovable project and use `<BrandIndex />` on the
Intelligence page. It only needs the JSON URL.

```tsx
// BrandIndex.tsx — VGR Brand Search Interest, reads the live data feed.
import { useEffect, useMemo, useState } from "react";

const DATA_URL = "https://<user>.github.io/<repo>/brand_index_data.json";

type Brand = {
  rank: number; brand: string; qid: string; tier: "A" | "B" | "C";
  interest_index: number; vgr_mom_pct: number | null; aug_rank: number | null;
  trends_level: number | null; search_mom_pct: number | null;
  news_level: number | null; news_mom_pct: number | null;
  wikipedia_pageviews: number | null; wiki_mom_pct: number | null;
  wikidata_url: string;
};
type Feed = {
  generated_at: string; month: string; n_brands: number; scale: string;
  method: { google_search_pct: number; google_news_pct: number; wikipedia_pct: number;
    attention_pct: number; breadth_pct: number; basket: string[]; basket_average: number };
  tiers: Record<"A" | "B" | "C", number>;
  top20: { brand: string; interest_index: number }[];
  movers: { risers: { brand: string; rank_change: number }[];
    fallers: { brand: string; rank_change: number }[] };
  brands: Brand[];
};

export default function BrandIndex() {
  const [d, setD] = useState<Feed | null>(null);
  const [q, setQ] = useState("");

  useEffect(() => { fetch(DATA_URL).then(r => r.json()).then(setD); }, []);

  const rows = useMemo(() => {
    if (!d) return [];
    const s = q.trim().toLowerCase();
    return s ? d.brands.filter(b => b.brand.toLowerCase().includes(s)) : d.brands;
  }, [d, q]);

  if (!d) return <div className="p-6 text-sm opacity-60">Loading…</div>;

  return (
    <section className="space-y-6">
      <header>
        <h2 className="text-2xl font-semibold tracking-tight">VGR Brand Search Interest — Top {d.n_brands} Fashion Brands by Attention</h2>
        <p className="text-sm opacity-60">
          Google search {d.method.google_search_pct}% · Google news {d.method.google_news_pct}% ·
          Wikipedia {d.method.wikipedia_pct}% — {d.scale} · {d.month} ·
          updated {new Date(d.generated_at).toLocaleDateString()}
        </p>
      </header>

      <div className="grid grid-cols-2 md:grid-cols-4 gap-3">
        <Kpi label="Brands" value={String(d.n_brands)} />
        <Kpi label="Tier A (elite)" value={String(d.tiers.A)} />
        <Kpi label="Tier B" value={String(d.tiers.B)} />
        <Kpi label="Tier C (long tail)" value={String(d.tiers.C)} />
      </div>

      <div className="rounded-2xl border p-4 overflow-x-auto">
        <div className="flex items-center gap-3 mb-3">
          <h3 className="text-sm font-medium">All {d.n_brands} brands</h3>
          <input className="border rounded-lg px-2 py-1 text-sm ml-auto"
                 placeholder="Search brand…" value={q} onChange={e => setQ(e.target.value)} />
        </div>
        <table className="w-full text-sm">
          <thead className="text-xs uppercase opacity-60">
            <tr>
              <th className="text-left py-1">#</th><th className="text-left">Brand</th>
              <th className="text-center">Tier</th><th className="text-right">VGR interest</th>
              <th className="text-right">% vs last mo</th><th className="text-right">g search</th>
              <th className="text-right">g news</th><th className="text-right">wikipedia</th>
            </tr>
          </thead>
          <tbody>
            {rows.map(b => (
              <tr key={b.qid} className="border-t">
                <td className="py-1 opacity-60">{b.rank}</td>
                <td>
                  <a href={b.wikidata_url} target="_blank" rel="noopener noreferrer"
                     className="text-indigo-500 hover:underline">{b.brand}</a>
                </td>
                <td className="text-center">{b.tier}</td>
                <td className="text-right tabular-nums font-semibold">{b.interest_index.toFixed(1)}</td>
                <td className={`text-right tabular-nums ${pos(b.vgr_mom_pct)}`}>{fmt(b.vgr_mom_pct)}</td>
                <td className="text-right tabular-nums opacity-70">{lvl(b.trends_level)}</td>
                <td className="text-right tabular-nums opacity-70">{lvl(b.news_level)}</td>
                <td className="text-right tabular-nums opacity-70">{b.wikipedia_pageviews?.toLocaleString() ?? "—"}</td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </section>
  );
}

const pos = (v: number | null) => v == null ? "" : v >= 0 ? "text-emerald-500" : "text-rose-500";
const fmt = (v: number | null) => v == null ? "new" : `${v >= 0 ? "+" : ""}${v.toFixed(0)}%`;
const lvl = (v: number | null) => v == null || v <= 0 ? "—" : v >= 10 ? Math.round(v).toLocaleString() : v.toFixed(1);
function Kpi({ label, value }: { label: string; value: string }) {
  return (
    <div className="rounded-2xl border p-4">
      <div className="text-xs uppercase opacity-60">{label}</div>
      <div className="text-2xl font-semibold mt-1">{value}</div>
    </div>
  );
}
```

Swap `DATA_URL` for your Pages JSON URL. That's the only edit. The component
re-fetches on load, so every publish shows up automatically.

## If you'd rather NOT use GitHub / the cloud
Keep it on your PC: run `python dashboard.py` and upload
`Brand_Index_Dashboard.html` + `brand_index_data.json` to wherever your site
reads them. Same files — it just only refreshes when you run it.

## Notes
- GitHub Pages serves the JSON with permissive CORS, so Lovable can `fetch()` it.
- The Action re-renders from committed CSVs only — it never invents data. Refresh
  the numbers by re-running the local collection and pushing the new CSVs.
